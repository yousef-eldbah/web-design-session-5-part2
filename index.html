Flexbox Child Properties / خصائص عناصر الـ Flexbox للأبناء

Control the alignment, sizing, and order of individual elements inside a Flex Container.

🛠 Concept & Why It Exists / الفكرة وسبب الوجود

While parent Flexbox properties (like justify-content or align-items) manage the layout globally, Child Properties allow developers to target individual flex items. This solved the old CSS layout problem of having to write float hacks, absolute positioning, or table structures just to make one block expand or shift position.

بينما خصائص الأب (Flex Container) بتتحكم في الشكل العام للتنسيق، خصائص الأبناء (Flex Items) بتخليك تتحكم في كل عنصر لوحده بدقة. وده حل مشكلة قديمة أوي في الـ CSS لما كنا بنحتاج نلجأ لحيل الطفو (floats) أو التموضع المطلق (absolute) عشان نكبر مربع واحد أو نغير مكانه.

Properties Breakdown

1. order

  • Simple Concept / الفكرة ببساطة: Rearranges elements visually on the screen without changing the HTML source code.
  • Why Created / لماذا تم إنشاؤها: To dynamically adjust visual flow across different responsive layouts (e.g. mobile vs desktop).
  • Problem Solved / المشكلة المحلولة: Eliminated the need to duplicate HTML elements or write complex JavaScript to move nodes around the page on window resize.
  • When to Use / متى تستخدمها: Responsive web layouts where an auxiliary column (like a sidebar) must move beneath or above the main text column on small mobile screens.
  • When NOT to Use / متى لا تستخدمها: Do not use it for keyboard tab focus navigation layouts, as the user will hit the tab key and jump in a chaotic visual sequence (breaks Web Accessibility).
  • Beginner Mistakes / أخطاء شائعة: Modifying the order of input form fields, causing screen readers to read fields in a confusing sequence.
  • Best Practices / أفضل ممارسات: Keep the source HTML order logical for SEO and Screen Readers, and use order only for decorative shifts.
  • Comparison / المقارنة: Unlike float and position, order keeps elements relative inside the flex flow and automatically respects flex wrapping rules.
order: بتغير الترتيب البصري للعناصر على الشاشة من غير ما نغير ترتيبهم في كود الـ HTML الأساسي. بتنفعك جداً مع الشاشات المتجاوبة عشان تنقل القائمة الجانبية تحت المحتوى الأساسي في الموبايل مثلاً. قيمتها الافتراضية 0 وتقدر تديها أرقام موجبة أو سالبة عادي.
Simple Code / مثال بسيط:
CSS
.card-highlight {
  order: -1; /* Makes this card appear before all other sibling items / يجعل هذا العنصر يظهر أولاً */
}
Real-world Component Example / مثال عملي من المشاريع:
CSS
/* Responsive Profile layout: Avatar appears first on mobile, details on desktop / ترتيب محتويات حساب العميل */
.user-avatar {
  order: 1; /* Shows first on mobile / يظهر أولاً على الموبايل */
}
.user-info {
  order: 2;
}

@media (min-width: 768px) {
  .user-avatar {
    order: 2; /* Switches position on larger screens / ينتقل للموضع الثاني في الشاشات الكبيرة */
  }
  .user-info {
    order: 1;
  }
}

2. flex-grow

  • Simple Concept / الفكرة ببساطة: Determines how much an element expands to fill empty space relative to its siblings.
  • Why Created / لماذا تم إنشاؤها: To allow developers to create dynamic expanding layouts (like sidebar/content ratios) without hardcoding percentages.
  • Problem Solved / المشكلة المحلولة: Solved complex calculations to divide remaining width when mixing static columns (e.g. 200px) with dynamic ones.
  • When to Use / متى تستخدمها: Search bars in navigation menus, content body sections in layouts, or dynamically sized grid cards.
  • When NOT to Use / متى لا تستخدمها: When you need strict, unbending column sizes (like exact thumbnail grids) where sizing must remain constant.
  • Beginner Mistakes / أخطاء شائعة: Thinking flex-grow: 2 makes an item twice the size of flex-grow: 1. It makes the item grow twice as fast, but starting base widths still affect total calculations.
  • Best Practices / أفضل ممارسات: Set flex-basis to 0 or 0% when using grow to guarantee absolute growth proportions.
  • Comparison / المقارنة: Unlike `width: 100%`, flex-grow expands only to consume *available remaining space* without overflowing parent boundaries.
flex-grow: بتحدد العنصر هيكبر ويملا المساحة الفاضية قد إيه بالنسبة لباقي العناصر. القيمة الافتراضية 0 (يعني مش هيكبر). لو أدينا عنصر قيمة 2 وعنصر تاني قيمة 1، الأولاني هيكبر بمعدل الضعف مقارنة بالتاني عشان ياكلوا المساحة المتاحة.
Simple Code / مثال بسيط:
CSS
.input-fill-space {
  flex-grow: 1; /* Consumes all remaining empty space / يملأ كل الفراغ المتبقي */
}
Real-world Component Example / مثال عملي:
CSS
/* Standard Search Navbar: Input grows, buttons remain static size / شريط بحث علوي */
.nav-container {
  display: flex;
  align-items: center;
}
.nav-logo {
  flex-grow: 0; /* Keep original size / يحافظ على حجمه الأصلي */
}
.search-input {
  flex-grow: 1; /* Takes all remaining space dynamically / يتمدد ليأخذ كل المساحة المتاحة */
}
.nav-btn {
  flex-grow: 0;
}

3. flex-shrink

  • Simple Concept / الفكرة ببساطة: Determines how much an element shrinks to prevent container overflow when spacing is tight.
  • Why Created / لماذا تم إنشاؤها: To safeguard layout layout boundaries and prevent elements from breaking out of containers.
  • Problem Solved / المشكلة المحلولة: Abolished overflow scroll issues and text break errors in compact row layouts.
  • When to Use / متى تستخدمها: To lock sizing of profile avatars, badges, or card icons so they never squeeze or morph when screen size scales down.
  • When NOT to Use / متى لا تستخدمها: When wrapping is allowed (flex-wrap: wrap), as items should wrap down to the next row instead of squeezing.
  • Beginner Mistakes / أخطاء شائعة: Wondering why icons turn oval. That's because default flex-shrink: 1 is compressing them. Prevent it by setting flex-shrink: 0.
  • Best Practices / أفضل ممارسات: Set flex-shrink: 0 on any decorative shape or image block that must retain circular proportions.
  • Comparison / المقارنة: Unlike `min-width`, flex-shrink: 0 is flexbox-native, meaning it won't break parent flex container limits.
flex-shrink: بتحدد العنصر ينكمش ويصغر قد إيه لما المساحة تضيق وميكفيش العناصر كلها جوة الأب. القيمة الافتراضية 1 (يعني العناصر بتكش بالتساوي). لو أديته 0، بتمنع العنصر ده إنه يصغر أو يكش نهائي (زي صور الأفاتار أو الأيقونات).
Simple Code / مثال بسيط:
CSS
.icon-circle {
  flex-shrink: 0; /* Never shrinks or morphs / يمنع العنصر تماماً من الانكماش والتغير */
}
Real-world Component Example / مثال عملي:
CSS
/* Comment widget list: Avatar stays static circular, text shrinks and wraps / قائمة التعليقات */
.comment-box {
  display: flex;
  gap: 16px;
}
.user-thumbnail {
  width: 60px;
  height: 60px;
  flex-shrink: 0; /* Keeps avatar perfectly circular / يحافظ على شكل الأفاتار دائري تماماً */
}
.comment-text {
  flex-grow: 1;
  flex-shrink: 1; /* Text box will shrink if screen goes narrow / ينكمش صندوق النص للتكيف */
}

4. flex-basis

  • Simple Concept / الفكرة ببساطة: Sets the initial starting width of a flex item before growth or shrinkage computations are applied.
  • Why Created / لماذا تم إنشاؤها: To replace standard width/height properties inside flex models, since parent flex direction changes axes dynamically.
  • Problem Solved / المشكلة المحلولة: Solved axes dependency confusion (width on row layouts vs height on column layouts).
  • When to Use / متى تستخدمها: To establish initial base percentages or pixel baselines (e.g. setting sidebar initial width to 280px).
  • When NOT to Use / متى لا تستخدمها: Do not set a strict pixel flex-basis if you want the layout to remain purely percentage-fluid without using media queries.
  • Beginner Mistakes / أخطاء شائعة: Forgetting that flex-basis overrides width (in row) or height (in column). Do not use both on the same selector as it causes redundancy.
  • Best Practices / أفضل ممارسات: Set flex-basis: 0% if you want items to size purely relative to flex-grow proportions.
  • Comparison / المقارنة: width is absolute, while flex-basis represents a *recommendation size* that the browser adjusts dynamically using shrink and grow values.
flex-basis: بتحدد العرض أو الحجم المبدئي للعنصر قبل ما ينكمش أو يكبر. دي البديل المباشر لـ width (لو إحنا شغالين row) أو الـ height (لو شغالين column). القيمة الافتراضية ليها auto.
Simple Code / مثال بسيط:
CSS
.column-left {
  flex-basis: 300px; /* Starting default size basis / الحجم الأساسي المبدئي 300 بكسل */
}
Real-world Component Example / مثال عملي:
CSS
/* Three columns grid layout inside landing pages / تخطيط أعمدة متساوية */
.row-grid {
  display: flex;
}
.col-item {
  flex-basis: 33.33%; /* Base size is split equally / تقسيم مساحة البداية بالتساوي */
  flex-grow: 1;
  flex-shrink: 1;
}

5. flex shorthand

  • Simple Concept / الفكرة ببساطة: Shortened syntax that combines grow, shrink, and basis.
  • Why Created / لماذا تم إنشاؤها: To speed up writing rules and force standard layout practices across engines.
  • Problem Solved / المشكلة المحلولة: Solved conflict bugs where browsers applied varying defaults to individual un-declared flex properties.
  • When to Use / متى تستخدمها: Always. W3C guidelines recommend using the shorthand instead of individual properties.
  • When NOT to Use / متى لا تستخدمها: None. Shorthand syntax is always preferred.
  • Beginner Mistakes / أخطاء شائعة: Writing flex: 1 and not understanding that it changes default flex-basis to 0% instead of auto.
  • Best Practices / أفضل ممارسات: Use clean configurations like flex: 1 (distribute equal space), flex: auto (grow/shrink based on content), or flex: none (same as 0 0 auto).
  • Comparison / المقارنة: Writing flex: 1 0 auto is much shorter and safer than writing three separate property declarations.
flex shorthand: بتلم الخصائص التلاتة (grow, shrink, basis) مع بعض في سطر واحد. أفضل ممارسة: استخدم الاختصار ده دايماً عشان تريح نفسك وتمنع أي مشاكل توافقية في المتصفحات. التركيبة بتاعتها: flex: [grow] [shrink] [basis]. والاختصار المشهور جداً flex: 1 بيساوي 1 1 0% وده بيخلي كل العناصر تتقسم بالتساوي بالظبط.
Simple Code / مثال بسيط:
CSS
.equal-flexible-box {
  flex: 1; /* Equivalent to: flex-grow: 1; flex-shrink: 1; flex-basis: 0%; */
}
Real-world Component Example / مثال عملي:
CSS
/* Split card design where media is fixed and body consumes rest / تقسيم بطاقة محتوى */
.premium-post-card {
  display: flex;
}
.card-media {
  flex: none; /* Same as: 0 0 auto. Stays static content size / لا ينمو ولا ينكمش */
  width: 150px;
}
.card-body {
  flex: 1; /* Takes all remaining space dynamically / يأخذ المساحة المتبقية كاملة */
}

Hiding Elements / إخفاء العناصر في CSS

Understand the critical differences between display:none, visibility:hidden, opacity:0, and pointer-events:none.

👁 Why & When / لماذا ومتى نخفي العناصر؟

In modern web applications, we frequently show and hide elements based on user interaction (menus, modals, tooltips, loading indicators). Choosing the wrong technique can lead to accessibility bugs, broken layouts, or broken transition animations.

في تطبيقات الويب الحديثة، نقوم بإخفاء وإظهار العناصر بكثرة بناءً على تفاعل المستخدم (القوائم، النوافذ المنبثقة، التلميحات). اختيار الطريقة الخاطئة قد يسبب مشاكل في إمكانية الوصول للموقع (Accessibility)، أو يكسر التصميم البصري، أو يعطل الحركات الانتقالية (Transitions).

Deep-Dive Hiding Methods / تفصيل تقنيات الإخفاء الأربعة

display: none;

  • Simple Concept / الفكرة ببساطة: Completely removes the element from the layout flow. It becomes invisible and takes zero pixels.
  • Why Created / لماذا تم إنشاؤها: To allow toggling content visibility on demand (e.g. tabs systems) without rendering spaces.
  • Problem Solved / المشكلة المحلولة: Replaced the old practice of shifting elements coordinates to `-9999px` off-screen, which caused performance rendering lags.
  • When to Use / متى تستخدمها: Dropdown menus, closed modals, or hidden tabs that are not currently active.
  • When NOT to Use / متى لا تستخدمها: When you want to animate a smooth transition (like fade-in), because the property is binary and cannot interpolate.
  • Beginner Mistakes / أخطاء شائعة: Forgetting that search engine bots might ignore content styled with display: none on load, harming SEO if not handled.
  • Best Practices / أفضل ممارسات: Combine it with aria-hidden tags to prevent accessibility readers from processing hidden structures.
  • Comparison / المقارنة: Unlike opacity, display: none recalculates layout reflow, shifting surrounding components.
display: none: بتشيل العنصر تماماً من الصفحة والمساحة بتاعته بتختفي كأنه مش موجود خالص. ومينفعش تعمل معاه حركات انتقالية (transitions) لأنه إما موجود أو مش موجود.
Simple Code / مثال بسيط:
CSS
.hidden-panel {
  display: none; /* Completely removed / يختفي كلياً ولا يحجز مساحة */
}
Real-world Component Example / مثال عملي:
CSS
/* Responsive mobile menu toggle / إخفاء القائمة في شاشات الديسكتوب */
.mobile-hamburger {
  display: block;
}

@media (min-width: 1024px) {
  .mobile-hamburger {
    display: none; /* Removed completely on desktop / يختفي تماماً في الشاشات الكبيرة */
  }
}

visibility: hidden;

  • Simple Concept / الفكرة ببساطة: Hides the element visually but preserves the space it occupies in the layout.
  • Why Created / لماذا تم إنشاؤها: To allow developers to hide items without causing shifts in surrounding elements.
  • Problem Solved / المشكلة المحلولة: Prevented layout recalculation (reflow) which triggers expensive CPU renders.
  • When to Use / متى تستخدمها: Loading icons that appear inside forms, error labels below input elements.
  • When NOT to Use / متى لا تستخدمها: General layouts toggle (e.g. mobile drawer menu) where empty layout space is unacceptable.
  • Beginner Mistakes / أخطاء شائعة: Expecting hidden form inputs to block focus navigation. Users can still tab key focus into hidden visibility fields if not careful.
  • Best Practices / أفضل ممارسات: Set tabindex="-1" to prevent focus issues when hidden.
  • Comparison / المقارنة: Unlike display, visibility: hidden respects layout geometries, leaving a blank hole.
visibility: hidden: بيخفي العنصر عن العين بس بيفضل حاجز مكانه ومساحته بالكامل في الصفحة كأنه مكان فاضي.
Simple Code / مثال بسيط:
CSS
.hidden-but-reserves-space {
  visibility: hidden; /* Invisible but layout holds / غير مرئي لكن المساحة محجوزة */
}
Real-world Component Example / مثال عملي:
CSS
/* Error labels below form inputs to prevent input boxes from moving up/down / إظهار وإخفاء رسالة الخطأ دون اهتزاز الحقول */
.error-label {
  color: var(--accent-red);
  height: 20px;
  visibility: hidden; /* Holds space so form doesn't shrink / يحجز المساحة لمنع اهتزاز التصميم */
}
.error-label.show {
  visibility: visible;
}

✨ Concept & Why It Exists / المفهوم العام للـ pseudo elements

🎨 Core Background & Color Properties / الأساسيات بالنقاط الـ 12

Background properties in CSS allow us to design beautiful layers. However, students frequently confuse background-size (for block backgrounds) with object-fit (for replaced DOM tags like images).

تنسيق الخلفيات والألوان بيخلي شكل الموقع ممتاز. بس المشكلة إن أغلب الطلاب بيتلخبطوا بين الـ background-size (اللي بتتحكم في حجم خلفية الـ CSS بتاعة المربع) والـ object-fit (اللي بتتحكم في شكل واقتصاص صورة حقيقية مكتوبة كـ tag <img> في الـ HTML).

Color Systems Compared / مقارنة نظم الألوان

  • HEX (#ff007f): Hexadecimal notation, compact, works everywhere. Difficult to modify opacity without modern HEX variants.
  • RGB / RGBA (rgb(255, 0, 127) / rgba(255, 0, 127, 0.5)): Red, Green, Blue values. RGBA adds Alpha (opacity) channel. Easy to read color density.
  • HSL (hsl(330, 100%, 50%)): Hue (0-360 color wheel), Saturation, Lightness. Excellent for developers to generate lighter/darker states programmatically.
  • Opacity: A global element property. If applied, it makes the entire element and all its children transparent. To make only background transparent, use RGBA or HSL transparency.
الفرق المهم جداً بين Opacity و RGBA: لو حطيت opacity: 0.5 على مربع، المربع ده وكل الكلام والصور اللي جواه هيبقوا شفافين مع بعض. لكن لو استخدمت background-color: rgba(0,0,0,0.5)، الخلفية بس هي اللي هتكون شفافة، وهيفضل النص اللي فوقيها واضح وظاهر بألوانه الكاملة من غير أي تأثير.

!important & Specificity / أولوية القواعد والـ Specificity

Understand the CSS hierarchy weight formula and how to avoid !important code smell.

⚡ Concept & Why It Exists / المفهوم وسبب الوجود

  • Simple Concept / الفكرة ببساطة: CSS stands for Cascading Style Sheets — when multiple rules target the same element, the browser uses a mathematical weight formula called Specificity to decide which rule wins.
  • Why Created / لماذا أُنشئت: Without specificity, CSS would have no conflict resolution — later rules would always override earlier ones regardless of selector precision.
  • Problem Solved / المشكلة المحلولة: Developers needed a predictable system to control which styles override others in large projects with hundreds of rules.
  • When to use !important / متى تستخدم: Only in global utility helpers like .d-none { display: none !important; } where absolute override is intentional.
  • When NOT to use !important / متى لا تستخدمها: Never as a "quick fix" for specificity conflicts in regular components — fix the selector instead.
الـ CSS اسمها كدة "Cascading" يعني فيه نظام أولويات. لما بيكون فيه أكتر من قاعدة بتستهدف نفس العنصر، المتصفح بيحسب حساب رياضي اسمه الخصوصية (Specificity) عشان يقرر مين اللي يكسب. من غير النظام ده، كانت القاعدة الأخيرة هتكسب دايماً مهما كانت التانية أدق منها.

The Weight Hierarchy / تراتيب القوة الحسابية

Specificity Weight Formula / معادلة حساب الأوزان

  1. Inline styles: style="color: red" (Specificity weight: 1,0,0,0)
  2. ID Selectors: #header (Specificity weight: 0,1,0,0)
  3. Class selectors, attributes, pseudo-classes: .card, :hover (Specificity: 0,0,1,0)
  4. Elements & pseudo-elements: div, ::before (Specificity: 0,0,0,1)

Specificity Calculation Examples / أمثلة حسابية عملية

CSS
/* Example 1: Element selector only / محدد عنصر فقط */
p { color: red; }
/* Specificity: 0,0,0,1 — weakest / الأضعف */

/* Example 2: Class selector / محدد كلاس */
.text-primary { color: blue; }
/* Specificity: 0,0,1,0 — beats element selector / يتغلب على محدد العنصر */

/* Example 3: ID selector / محدد ID */
#main-title { color: green; }
/* Specificity: 0,1,0,0 — beats class selector / يتغلب على الكلاس */

/* Example 4: Combined selectors / محددات مجمعة */
div.container #sidebar .widget { color: purple; }
/* Specificity: 0,1,2,1 → (1 ID + 2 classes + 1 element) / محدد مركب قوي */

/* Example 5: Inline style always wins (unless !important) / الأسلوب المضمن يفوز دائماً */
/* <p style="color: orange"> → Specificity: 1,0,0,0 */
💡
Common Beginner Mistake / خطأ شائع للمبتدئين
Students often think the order in the CSS file always determines the winner. Wrong! Specificity weight is calculated first — only when two selectors have equal specificity does order matter (last one wins).
كتير من الطلاب فاكرين إن ترتيب الكود في ملف الـ CSS هو اللي بيحدد مين يكسب دايماً. غلط! المتصفح بيحسب ثقل الخصوصية الأول — بس لو الثقل طلع متساوي، ساعتها بس الترتيب بيفرق (الأخير بيكسب).

What is !important & When is it acceptable? / متى نقبل كتابة !important ومتى نمنعها؟

Applying !important overrides any specificity calculation, making that rule force-win. This creates issues later when debugging.

لما تكتب !important جنب أي قيمة، بتلغي كل الحسابات وبتجبر القاعدة دي تكسب غصب. ده بيتعتبر Code Smell (علامة كود وحش) في المشاريع الكبيرة لإنه بيخلي التعديل بعد كدة مستحيل.

❌ Forbidden / متى يُمنع استخدامها

Do NOT use it to solve specificity issues on general stylesheet classes or component structure. Instead, solve it by writing cleaner selectors.

CSS
/* ❌ BAD: Fighting specificity with !important / سيء: محاربة الخصوصية بالقوة */
.title {
  color: red !important; /* Don't do this! / لا تفعل هذا! */
}

/* ✅ GOOD: Increase specificity properly / جيد: زيادة الخصوصية بالطريقة الصحيحة */
.card .card-title {
  color: red; /* More specific selector / محدد أكثر دقة */
}

✅ Acceptable / متى يُقبل استخدامها

Acceptable on global utility overriding helper classes where we want absolute enforcement.

CSS
/* ✅ Utility classes that MUST always win / فئات المساعدة التي يجب أن تفوز دائماً */
.d-none { display: none !important; }
.text-center { text-align: center !important; }
.sr-only { /* Screen reader only / مخصص لقارئات الشاشة فقط */
  position: absolute !important;
  width: 1px !important;
  height: 1px !important;
  overflow: hidden !important;
}

Best Practices / أفضل الممارسات

Specificity Debugging Checklist / قائمة تشخيص مشاكل الخصوصية

  1. Use DevTools: Right-click → Inspect → check which rule is winning (shown as active, others are struck-through). / افتح الـ DevTools وشوف أنهي قاعدة كاسبة (اللي خاسرة بتلاقيها عليها خط يشطبها).
  2. Count the weights: IDs > Classes > Elements. Write them as (a,b,c,d). / احسب الأوزان: الـ ID أقوى من الكلاس أقوى من العنصر.
  3. Avoid deep nesting: body div.container section article .card .title is too specific and brittle. / متعملش selectors طويلة أوي متداخلة — كل ما طولت كل ما التعديل بعد كدة هيبقى صعب.
  4. Use BEM naming: .card__title--active keeps specificity flat and predictable. / استخدم طريقة الـ BEM في تسمية الكلاسات عشان الخصوصية تفضل مستوية ومتوقعة.

🔄 Resetting and Inheriting values / إعادة التعيين والوراثة

Sometimes you need to reset an element's property back to its default state or force it to copy the value from its parent. This is where CSS global keywords come in.

ساعات بنحتاج نرجع خاصية معينة لقيمتها الافتراضية، أو نجبرها تاخد نفس القيمة اللي واخدها العنصر الأب (الـ parent). الكلمات المفتاحية العالمية دي بتديلك تحكم كامل في وراثة التنسيقات من غير ما تلف وتدور كتير.

inherit Forces the element to take the exact same property value as its parent. بيجبر العنصر إنه يورث نفس القيمة بالظبط من أبوه (الـ parent).

Vendor Prefixes / البادئات الخاصة بالمتصفحات

Understand what they are, why they were used, and how Autoprefixer automated this process.

🔧 Concept & History / الفكرة والماضي

Years ago, when CSS3 was introduced, browser engines implemented new features (like animations, grids, transitions, or gradients) experimentally. To prevent breaking other browsers, each engine forced developers to use prefix flags.

زمان، لما نزل الـ CSS3، كانت شركات المتصفحات (جوجل، أبل، مايكروسوفت) بتجرب الخصائص الجديدة زي الـ transitions والـ gradients بشكل تجريبي. وعشان كودهم ميبوظش شغل بعض، كل شركة عملت لنفسها "بادئة" أو كلمة سر لازم المطور يكتبها قبل الخاصية عشان تشتغل في المتصفح ده.

The Prefixes / البادئات الأربعة الشهيرة

  • -webkit-: Chrome, Safari, newer Opera, iOS.
  • -moz-: Mozilla Firefox.
  • -ms-: Internet Explorer & early Edge.
  • -o-: Old Opera versions.

Are we still writing prefixes? & Autoprefixer / هل ما زلنا نكتبها؟ والـ Autoprefixer

Writing prefixes manually leads to massive, unmaintainable stylesheets. In modern workflow, developers write clean, standard CSS, and use build tools like Autoprefixer (integrated in PostCSS, Vite, Webpack) to append prefixes automatically based on target browser markets statistics.

كتابة البادئات دي يدوي كانت كابوس وبتملا الملف تكرار وحشو مالوش لازمة. النهاردة في الشغل الحقيقي، إحنا بنكتب كود CSS قياسي عادي ونضيف جداً، وبنسيب أداة ذكية اسمها Autoprefixer (بتكون مدمجة مع أدوات زي Vite أو Webpack) هي اللي تتدخل وتدور في قواعد البيانات وتزود البادئات المناسبة للمتصفحات القديمة أوتوماتيك.
